# Rust-порт бота розыгрышей — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development или
> superpowers:executing-plans. Шаги — чекбоксы `- [ ]`.

**Goal:** один Rust-процесс (teloxide + SQLite) с поведением Python `9a4c9c6` по docs/PARITY.md.

**Architecture:** long polling → per-user lock → хендлеры читают/пишут состояние
`dialogues` и данные в SQLite; рассылки и Sheets — фоновые задачи; все отправки через
`teloxide::Bot` (в тестах — wiremock).

**Tech Stack:** Rust 1.98.1, teloxide 0.17 (rustls), sqlx 0.8 sqlite, tokio current_thread,
chrono, rand 0.9, ring + base64 (уже в дереве через rustls/reqwest), reqwest 0.12,
serde/serde_json, anyhow, tracing; dev: wiremock, tempfile.

**Spec:** docs/SPEC.md, docs/PARITY.md.

## Global Constraints

- Тексты — побайтно из Python: `bot/messages/messages.json` копируется как есть; строки,
  зашитые в Python-хендлерах, переносятся дословно (эмодзи, `\n`, HTML-теги).
- `callback_data` — те же строки, что в Python (`admin:*`, `nav:*`, `start_time:*`,
  `duration:*`, `preview:*`, `announce:*`, `announce_manual:*`, `giveaway:*`,
  `winners:*`, `results:*`, `broadcast:*`, `suspicious:*`, `verify:<n>`).
- Все отправки — `ParseMode::Html`.
- Время в БД — TEXT RFC 3339 UTC, микросекунды, суффикс `Z`. Показ — МСК (UTC+3 фиксированно).
- Токен никогда не попадает в лог; `ADMIN_IDS`/`CHANNEL_ID` не логируются.
- Порог каждой задачи: `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`,
  `cargo test` — зелёные. Функции ≤ 50 строк, файлы ≤ 400 строк.
- Коммит после каждой задачи, `git -c safe.directory='*'`, Conventional Commits,
  трейлер `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`.

### Task 4: Рассылки — очередь, отправка, worker

**Files:** src/db/mailings.rs, src/mailing.rs, tests/mailing.rs.

**Produces:**
- `Content { text: Option<String>, media: Option<(String /*type*/, String /*file_id*/)>,
  join_button: bool }`; `send_content(bot, chat: ChatId, &Content, join_url) -> Result<(), RequestError>`
  (photo/video/animation/document с caption, иначе message; кнопка «🎁 Участвовать» → URL).
- `NewMailing { kind: Kind, content, to_channel: bool, audience: Audience /*None|Users|Admins*/,
  rps, report_chat, report_message }`; `Kind = Broadcast|Announce|AnnounceNew|Results`
  (определяет итоговый текст); `db.enqueue(NewMailing) -> i64`.
- `mailing_worker(bot, app)` — бесконечный цикл: взять `running`, иначе старейший `queued`;
  `run_mailing` → итог; ждать `Notify` или 5 с.
- `run_mailing`: канал (флаг `channel_done`), затем пачки получателей `user_id > cursor AND
  joined_at <= created_at` (или ADMIN_IDS), для каждого: `advance(cursor=user)` → send →
  `count(sent|failed)`; 429 → sleep retry_after, повтор ≤ max_retries; после каждой попытки
  `sleep(1/rps)`; лог каждые 100; финал: `finish` + edit сообщения отчёта (ошибка edit —
  только лог).
- Итоговые тексты дословно из Python: broadcast (`✅ <b>Рассылка завершена!</b>…` со
  «Всего пользователей», «Длительность: X.Xс»), announce (`✅ Анонс отправлен!\n\n📊 Отправлено: N`),
  announce-new (+ `\n🎁 Розыгрыш активен!`), results (`✅ Результаты опубликованы!\n\n📊 Отправлено: N`).
  Пустая аудитория рассылки — проверяется хендлером до enqueue.

- [ ] Тесты (wiremock, `tokio::time::pause` там, где нет реального I/O): все доставлены;
  403 → failed; 429 retry_after=1 затем ok → sent; 429 больше max_retries → failed; медиа по
  типу вызывает нужный метод; канал + пользователи = канал считается 1 раз; «рестарт»:
  прервать после 2 из 5 (mock падает таймаутом/паника worker'а через drop), новый worker
  доотправляет 3, общий счёт запросов sendMessage = 5 (+1 в полёте считается failed), без
  дублей; снимок: пользователь, добавленный после enqueue, не получает; админская аудитория;
  отчёт редактируется итоговым текстом.
- [ ] Реализация, коммит `feat: persistent mailing queue`.
